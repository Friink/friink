# Friink R2 Setup Guide

This guide records the R2 configuration used for Friink staging so the same
process can be repeated for production. It covers profile-picture uploads.
Post-media uploads are not wired yet.

## Important security rule

Never commit or paste R2 secrets into GitHub, `R2.md`, `README.md`, screenshots,
or chat. Use placeholders in documentation and enter real values only into the
appropriate Vercel environment variables.

The application uses the S3-compatible credentials below:

- Account ID
- Access Key ID
- Secret Access Key
- Bucket name
- Public object URL

The Cloudflare API token is not used by the Friink upload code. The application
uses the Access Key ID and Secret Access Key for the S3-compatible R2 API.

## 1. Create a separate bucket

Create one bucket for each environment. Do not reuse the staging bucket for
production.

Recommended names:

```text
friink-staging
friink-production
```

In Cloudflare:

1. Open **R2 Object Storage**.
2. Create or select the environment bucket.
3. Copy the bucket name exactly, including capitalization and hyphens.
4. Keep the bucket private for direct writes. Public read access is configured
   separately in the next step.

## 2. Enable the public object URL

Profile-picture URLs are stored in the database and displayed by the web app,
so the objects need a public read URL.

1. Open the bucket's **Settings** page.
2. Under **Public Development URL**, select **Enable**.
3. Copy the generated URL, for example:

```text
https://pub-<bucket-id>.r2.dev
```

4. Set this as `R2_PUBLIC_URL` without a trailing slash.

The public URL is read-only from the application's perspective: uploads still
use private presigned `PUT` URLs generated by the API. Anyone who knows a
published object URL may read that object, so do not store private media there.

## 3. Configure bucket CORS

On the bucket's **Settings** page, open **CORS Policy**, select **Add**, and
save a policy containing every web origin that will upload directly to R2.

For production, use:

```json
[
  {
    "AllowedOrigins": [
      "https://friink.com"
    ],
    "AllowedMethods": [
      "PUT"
    ],
    "AllowedHeaders": [
      "Content-Type"
    ],
    "ExposeHeaders": [
      "ETag"
    ],
    "MaxAgeSeconds": 3600
  }
]
```

For staging, use the staging origin instead:

```json
[
  {
    "AllowedOrigins": [
      "https://staging.friink.com"
    ],
    "AllowedMethods": [
      "PUT"
    ],
    "AllowedHeaders": [
      "Content-Type"
    ],
    "ExposeHeaders": [
      "ETag"
    ],
    "MaxAgeSeconds": 3600
  }
]
```

If the same bucket is temporarily used by both environments, include both
origins in one policy. Separate buckets are preferred for production.

## 4. Create R2 S3 API credentials

Create an R2 API token/access key with permission limited to the environment's
bucket. The Friink API needs to:

- create presigned upload URLs;
- inspect uploaded profile-picture objects; and
- delete the previous profile picture when it is replaced.

Copy the generated **Access Key ID** and **Secret Access Key** immediately and
store them in a password manager. The secret is shown only when created.

Use the S3 endpoint format:

```text
https://<account-id>.r2.cloudflarestorage.com
```

The application adds the bucket name separately; do not put the bucket name in
`R2_ACCOUNT_ID`.

## 5. Add variables to the FastAPI Vercel project

Friink has separate Vercel projects. Add the R2 values to the **API/FastAPI
project**, not the Next.js web project.

In Vercel, open the API project → **Settings** → **Environment Variables** and
add these five variables:

| Variable | Production value |
|---|---|
| `R2_ACCOUNT_ID` | Cloudflare account ID |
| `R2_ACCESS_KEY_ID` | R2 Access Key ID |
| `R2_SECRET_ACCESS_KEY` | R2 Secret Access Key |
| `R2_BUCKET_NAME` | Production bucket name |
| `R2_PUBLIC_URL` | Production `https://pub-...r2.dev` URL or approved custom domain |

For production, select **Production** for each variable. Do not select Preview
unless the variable is also intended for preview deployments.

Also confirm the API project has its normal production variables, especially:

- `DATABASE_URL`
- `JWT_SECRET_KEY`
- `FRONTEND_URL=https://friink.com`
- `ENVIRONMENT=production`

The API reads these variables at runtime. Changing them requires a new API
deployment.

## 6. Confirm the web Vercel project points to the production API

In the separate Next.js web project, set the production environment variable:

```text
NEXT_PUBLIC_API_BASE_URL=https://api.friink.com
```

Use the actual production API hostname if it differs. Do not put R2 secrets in
the web project; browser code only receives a short-lived presigned upload URL.

## 7. Deploy in the correct order

1. Save the production R2 configuration in Cloudflare.
2. Add the five R2 variables to the API Vercel project's **Production** scope.
3. Redeploy the API project from the production branch.
4. Confirm the API deployment is using the intended commit and production
   environment.
5. Confirm `NEXT_PUBLIC_API_BASE_URL` in the web project's Production scope.
6. Redeploy the web project.

Vercel environment variables are deployment-time configuration. Saving a value
does not change an already-running deployment until that project is redeployed.

## 8. Verify the setup

Use a real signed-in account on the production site:

1. Select a profile picture.
2. Adjust the square crop and confirm it.
3. Confirm the browser performs a `PUT` to the presigned R2 URL.
4. Confirm the profile picture appears after the page is refreshed.
5. Replace it with a second picture.
6. Confirm the new picture remains after refresh and the old object is removed
   from the production bucket.

The API routes are:

```text
POST /auth/me/profile-picture/upload-url
POST /auth/me/profile-picture/confirm
```

The second request must be authenticated. Swagger may be available on staging
for diagnostics, but production API documentation is disabled by design.

## Troubleshooting checklist

- **Browser blocks the R2 PUT:** check the bucket CORS policy and make sure the
  exact web origin is present, including `https://` and no trailing slash.
- **API says R2 is not configured:** check all five R2 variables in the API
  project's correct Vercel environment, then redeploy the API.
- **Upload succeeds but confirmation fails:** verify the API deployment commit,
  bucket name, Access Key permissions, and public object URL. Check the API
  deployment logs for the confirmation request.
- **The picture works only after a redeploy:** the variables were saved in
  Vercel but were not present in the running deployment.
- **Old objects remain:** replacement cleanup is mandatory for the current
  profile URL. Orphaned files from failed historical attempts may need a one-time
  manual review in the bucket.

## Environment-file reference for local development

For local-only testing, use an ignored file such as `api/.env.r2staging` or
`api/.env.r2production`. Never commit it. The variable names must match
`api/.env.example` exactly:

```text
R2_ACCOUNT_ID=
R2_ACCESS_KEY_ID=
R2_SECRET_ACCESS_KEY=
R2_BUCKET_NAME=
R2_PUBLIC_URL=
```

The production Vercel values are authoritative for production; the local file
is only for local testing.
