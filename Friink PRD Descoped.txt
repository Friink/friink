1. Overview
Friink is a software platform that combines community and a service marketplace. Focusing on mental health, it’ll provide a platform to interact with professionals and avail their services.
2. Auth
   1. Signup
As a prospective user, I want to create an account with my email, a unique username, and my date of birth, so that I can securely access the platform.


      1. Users can sign up with a unique email address.
      2. Passwords must be at least 8 characters long and must include 1 uppercase letter, 1 lowercase letter, 1 special character, 1 number, and no spaces.
      3. 6 letter (alphanumeric) OTP will be sent for email confirmation.
      4. Username can contain only letters, numbers, ‘-’, ‘_’, ‘.’, and no spaces.
         1. Username must be unique.
      5. At the time of registration the user must be at least 13 years old based on the date of birth they enter.
      6. Location can be left empty at the time of registration.
      7. Email will be sent after successful registration.
      8. If registration fails due to OTP verification or is left incomplete then the same email will be available to be reused immediately.
   2. Login
As a registered member, I want to authenticate via my email, password, and a fresh verification code, so that my account remains protected from unauthorized entries. 


      9. Users can login after registration with their email and password.
      10. OTP will be sent on registered email every time a user tries to login.
      11. Five consecutive failed attempts will lead to the account being blocked for 3 hours.
3. Users and Profiles
   1. Default User
As a default user, I want a profile initialized automatically at signup, so that I can interact with the community feed and explore available services. 


      12. All users are default at the time of registration.
      13. Default users can create posts.
      14. Default users can like, star, quote, and share posts.
      15. Default users can request service.
      16. Default users can like, star, and share services.
   2. Professional
As a default user who is a mental health practitioner, I want to apply for professional verification, so that I can unlock a verified badge and host services. 


      17. A default user can get verified to become a professional.
         1. In order to get verified they’ll have to;
            1. Enter their legal full name.
            2. Provide a short introduction for the reviewer.
            3. Submit supporting documents.
         2. The application to become a professional must be reviewed by a human moderator.
      18. Upon verification a verified badge will be given to a professional user.
      19. Professional users have all the access given to default users, in addition they can also create services.
      20. Professional users will have to set their location.
4. Feed
   1. Home
As a logged-in user, I want to view a personalized main homepage timeline, so that I can see relevant community posts. 


      21. Posts from all users will be shown based on user profile and interactions.
   2. Connections
As a network-focused user, I want a separate feed stream dedicated exclusively to my circles, so that I don't miss updates from people I choose to follow. 


      22. Posts from followers and following will be shown here.
5. Post
   1. Create
As a community member, I want to compose text and attach media updates, so that I can share my thoughts with the network. 


      23. Any user can create a post.
      24. A post can have 512 characters.
      25. Users can attach media that must be compressed at the time of upload.
      26. Limit upload to 16 files max.
   2. Quote
As a user responding to content, I want to quote another person's post, so that I can add my own commentary alongside their original text. 


      27. Using the quote button a user may create a quoted post.
   3. Share Internal
As an active chatter, I want to forward public posts directly into private chat threads, so that I can discuss them with connections 


      28. Users can share posts via chat.
   4. Share External
As a creator, I want to share posts outside the platform using a deep link, so that external audiences can discover my content. 


      29. Users can share posts externally via link.
      30. Share external will only be available if a user allows external sharing.
      31. By default external sharing will be turned on.
6. Search
   1. Global
As a user looking for specific items, I want a universal global keyword search engine, so that I can find matching accounts and post entries. 


      32. Global search is available to every user.
      33. The search tab will let users search for other users.
         1. Users can search using part of usernames and names.
      34. The search tab will let users search for posts.
         1. Users can search for posts using phrases from posts.
         2. The search result can include results from users that don't have the search phrase in their post but in their username.
   2. Directory
As a user seeking professional care, I want to browse structured directories of practitioners and options, so that I can evaluate them based on location and performance. 


      35. Users can access the directory from the side drawer.
      36. The Professionals tab will show professionals.
         1. Professionals will be sorted based on rating and location.
      37. The Services tab will show services.
         1. Services will be sorted based on professional rating, connection status, and location.
   3. Starred
As an organized user, I want to view my saved items, so that I can recall vital data. 


      38. Users can access starred items from their side drawer.
   4. Chat
As an organized user, I want to query specific conversations, so that I can recall vital data. 


      39. Users can search for users and phrases in chat from messages.
7. Chat
   1. Messages
As a private communicator, I want to trade direct text and rich multimedia messages with others, so that I can discuss topics privately. 


      40. Users can send text messages.
      41. Users can attach pictures, audio, and video files.
         1. The same data rules as post will be applied to attachment.
   2. Call (Out of Scope)
As a user needing real-time interaction, I want to launch voice or video calls inside a private message thread, so that I can speak with connections directly. 


      42. Users can initiate a call from within chat.
         1. Calls can be audio and video.
      43. Users can share video while in a call to make it a video call.
         1. The user on the other side will get a prompt to convert a call into video call.
      44. Video calls will be used for service requests.
   3. Updates
As a customer tracking orders, I want automated transaction logs sent inside my chat threads, so that I can track system changes easily. 


      45. Some service request notifications will be sent via chat for redundancy.
8. Connections
   1. Followers
As a social networking user, I want a dual-handshake follow request pipeline, so that I can safely control my personal circle.


      46. A user will be added to followers once they receive and accept a follow request.
   2. Following
As a social networking user, I want a dual-handshake follow request pipeline, so that I can safely control my personal circle. 


      47. A user will start following another user once their follow request is accepted.
9. Service
   1. Create
As a verified practitioner, I want to construct detailed service offerings, so that default users can purchase them. 


      48. Professionals can make services.
      49. A service must have a title of not more than 128 characters.
      50. A service can have a description of not more than 256 characters.
   2. Request
As a client, I want to submit formal service applications with attached notes, so that the provider can review my case.


      51. Any user can request service.
      52. Users can attach a note called “Request” while requesting.
         1. The note must not be more than 1024 characters.
      53. The request will have “New” status while it’s created and not opened. (Out of Scope)
      54. Once the provider opens the request it’s status will be updated to “Opened”. (Out of Scope)
      55. The professional can accept service, suggest another time, or decline. (Out of Scope)
         1. The status if accepted will be “Accepted”. (Out of Scope)
         2. The status if another time suggested will be “Pending”. (Out of Scope)
         3. The status will be “Declined” and then “Closed” if declined. (Out of Scope)
      56. Upon time agreement a payment link will be sent to the requester via email, chat, and notifications. (Out of Scope)
      57. Upon payment an event will be created and shown in the calendar to both provider and subscriber. (Out of Scope)
      58. If a request is declined and closed the user will get notified via email, chat, and notifications. (Out of Scope)
      59. Once the request is closed after being accepted, the provider will be able to add notes not more than 1024 characters. (Out of Scope)
      60. Once the request is closed after being accepted, the user will get an option to download details in a PDF file or share details both internally and externally via a link. (Out of Scope)
   3. Event (Out of Scope)
As a participant, I want a clear record of my scheduled video sessions, so that I can monitor my treatment history. 


      61. An event will be created after successful payment.
      62. The event will be a video call scheduled in the calendar.
      63. If both participants miss the event, they will get an option to mark it done or request reschedule.
      64. No refund will be offered in case of missing the event.
      65. Refund policy? Tech issue?
   4. Tracking (Out of Scope)
As a participant, I want a clear record of my scheduled video sessions, so that I can monitor my treatment history. 


      66. Request history will be saved and accessible in the service requests page for every request.
      67. In addition to statuses defined in 9.2, additional status will be;
         1. Event, when event is started either by provider or subscriber.
         2. Once both participants leave the event, the status will change to closed.
   5. Feedback
As a consumer, I want to rate my completed sessions, so that I can share my experience with the community directory. 


      68. Once an accepted request is closed, the subscriber will be asked to give feedback via notifications.
      69. The feedback will have an option to rate service and add comments, not more than 512 characters.
10. Calendar (Out of Scope)
   1. Month View
As a scheduled user, I want a clean, interactive month view calendar grid, so that I can track my upcoming sessions. 


      70. The calendar will be the primary method to view events created upon service request acceptance.
      71. Users will be able to jump to dates using the calendar.
   2. Events
As a scheduled user, I want a clean, interactive month view calendar grid, so that I can track my upcoming sessions. 


      72. The calendar will show a scrollable list of all events below the month.
         1. The list will default to the nearest upcoming event.
      73. Events will have a video call link embedded in the join button.
11. Notifications
   1. Push
As a user, I want to receive real-time push alerts for social interactions and vital account updates, so that I can stay engaged with the platform. 


      74. Users will be notified for;
         1. Likes on their posts.
         2. A user quotes their post.
         3. Comment on their post.
         4. Update on their service request. (Out of Scope)
         5. 15m before an event. (Out of Scope)
         6. Follow request.
         7. Someone unfollows them.
         8. Service request. (Out of Scope)
         9. Profile verification.
         10. Professional status revoked.
         11. Someone tries to login with their credentials.
         12. Successful login on another instance.
         13. Notes added to service request. (Out of Scope)
         14. Service feedback. (Out of Scope)
         15. Payment link generated. (Out of Scope)
         16. Payment successful. (Out of Scope)
         17. Failed professional verification.
         18. Event created. (Out of Scope)
         19. Password updated.
         20. Payments and subscriptions.
   2. In App
As an active user, I want a centralized native notification center, so that I can view all system alerts directly inside the app interface. 


      75. All the push notifications.
      76. In addition to push notifications;
         1. On the day of an event. (Out of Scope)
   3. Email
As a user, I want to receive formal email logs for critical profile and security milestones, so that I have a permanent transactional record. 


      77. Users will be notified for;
         1. Successful registration.
         2. Login attempt.
         3. Successful login.
         4. Service request creation. (Out of Scope)
         5. Service request update. (Out of Scope)
         6. Payment link created. (Out of Scope)
         7. Payment successful. (Out of Scope)
         8. Professional verification.
         9. Failed professional verification.
         10. Professional status revoked.
         11. Event created. (Out of Scope)
         12. Password updated.
         13. Payments and subscriptions.
   4. Chat
As a user, I want to receive updates via chat for critical service updates, so that I’m in sync with my service provider.


      78. Users will be notified for;
         1. Service requests. (Out of Scope)
         2. Payment link. (Out of Scope)
         3. Event started. (Out of Scope)
12. Settings
   1. Profile
As a user, I want to update my basic profile information and security handles, so that my account remains accurate and personalized.


      79. Users will be able to update;
         1. Name.
         2. Handle.
            1. Once every 24 hrs.
            2. OTP verification required.
            3. The older handle becomes available to other users after 24 hours.
            4. Can revert to the older handle within 24 hours without OTP verification or can change back once it’s available after the grace period.
         3. Profile picture.
         4. Date of birth.
         5. Email.
            1. OTP verification required.
   2. Professional Status
As a verified professional, I want to toggle my professional visibility status on or off, so that I can control when I am actively taking clients. 


      80. Professional will be able to;
         1. Turn on or off their professional status.
            1. OTP verification required.
   3. Security
As a user, I want to update my account password securely, so that I can keep my account protected. 


      81. Users will be able to update;
         1. Password.
            1. Must enter the existing password.
            2. Must meet password criteria.
            3. OTP verification required in case of forgotten password.
            4. The new password cannot be the same as the current or last two passwords.
13. Payments & Subscriptions
   1. Professional
As a verified professional user, I want to manage my monthly subscription and understand the grace period limits, so that I can maintain my business presence or seamlessly recover it after a lapse.


      82. A fixed fee of USD 1 after being verified for 1 month.
         1. All payments to be processed via an external link on Friink website.
         2. Automatic payment toggle will appear every time the user pays manually.
      83. Subscription will be cancelled after 7 days of non payment.
         1. Professional status will be disabled.
         2. Users can resubscribe within 90 days without verification.
            1. After 90 days verification data will be marked as outdated and the user will have to use the verification flow again.
