# Media Upload MIME-Type Note

## What MIME type means

A MIME type identifies the kind of file being transferred. For example,
`image/jpeg` identifies a JPEG image, `image/png` identifies a PNG image, and
`application/pdf` identifies a PDF document.

## Current implementation

- The browser prepares post-media files as JPEGs.
- The API generates presigned R2 upload URLs with `Content-Type: image/jpeg`.
- The API validates the authenticated user's post-media key and namespace.
- Confirmation does not inspect the uploaded bytes or independently verify the
  actual MIME type or byte size.

## Risk

MIME type is metadata supplied by the client and should not be treated as a
security boundary. A malicious client could potentially upload non-JPEG bytes
under a `.jpg` key. The result could be a broken image or a security concern if
the media host serves user-controlled content with unsafe headers and the
browser interprets it as executable content.

This is currently a limitation to track, not proof of an immediate
vulnerability. The browser-side JPEG preparation and storage key validation
still enforce the intended normal upload path.

## Safer follow-up

If stronger validation is required, verify the stored object through a trusted
server-side mechanism, such as authenticated storage metadata inspection,
trusted upload constraints, or server-side byte inspection. Media delivery
should also use safe response headers, including an appropriate image
`Content-Type` and a deliberate `Content-Disposition` policy.

## Authentication conflicts captured

The following conflicts were identified while synchronizing `login.md`,
`forget-password.md`, and `auth-incident-response.md` with `RULES.md`:

1. Password recovery requires durable outbox delivery that does not block or
   change the neutral response, but the current password-reset endpoint
   directly awaits `EmailService.send_password_reset()`.
2. The active security-event rule requires notification processing to be
   non-blocking, but the current login path processes the notification outbox
   synchronously before returning the response.
3. The incident-response runbook requires recording the operator, but the
   internal auth-operation implementation records the target, reason, scope,
   and result without identifying the human operator.
