# Documentation and Business-Rule Capture — 2026-09-12

## Purpose

This is an audit capture, not a correction. It compares every document under
`docs/` with `RULES.md`, then checks each meaningful difference against the
current implementation. `RULES.md` and the existing design/feature documents
were intentionally left unchanged.

## Audit method and precedence

I read all current Markdown documents under `docs/` and the complete
`RULES.md`. The files under `docs/session/` were reviewed for context, but are
archival reference material and are excluded from the active comparison. The
latest dated or explicitly later focused contract wins over an older document.
A document with no embedded date is not assumed to be newer merely because it
is more specific. In particular:

- `docs/posts.md` is the latest post/reply/Quote contract.
- `docs/progressive-login.md` is the latest progressive-entry contract.
- `docs/failed-login-policy.md` is the latest failed-login policy.
- `docs/auth-and-session.md` (last updated `2026-09-10T13:30:00Z`) is the
  current authentication/session baseline and latest implementation document
  for that area.
- `docs/progressive-login.md` and `docs/failed-login-policy.md` are later,
  focused auth amendments recorded in the 2026-09-11 implementation/audit
  history. They supersede the baseline only for their respective progressive
  entry and failed-login slices; they do not replace the session model in
  `auth-and-session.md`.
- `docs/session/` is an old reference-docs repository and does not participate
  in deciding active requirements or conflicts.
- `packages/design/design.md` is the visual/component contract; it does not
  replace product business rules.

## What is not a conflict

The following apparent differences were resolved by applying document
precedence rather than by changing code:

- Mobile authentication is explicitly deferred; its absence is not a bug.
- Subscriptions remain an admin-only API foundation; the docs do not promise a
  user-facing subscription product yet.
- The lifecycle document’s open full-gate status agrees with `RULES.md`.
- `docs/login.md` and portions of `auth-and-session.md` contain historical
  incident/progress material. They should not override newer focused contracts
  unless their status is explicitly current. Files under `docs/session/` are
  excluded entirely from the active comparison.

## Recency correction

The first version of this capture treated `auth-and-session.md` as if it were
the newest source for every authentication detail. That was incorrect. Its
explicit timestamp is `2026-09-10T13:30:00Z`; the progressive-login work and
focused amendments were recorded on `2026-09-11`. The corrected interpretation
is therefore:

- `auth-and-session.md` remains authoritative for the current session model
  and shared authentication baseline.
- `progressive-login.md` is newer for `/start`, neutral progressive entry,
  and its beta rollout state.
- `failed-login-policy.md` is newer for failed-login throttling and its UX.
- Neither later focused document silently changes unrelated rules in
  `auth-and-session.md`.
